# Round-2 security findings: iOS response

- CA-1 (room link joins straight away): fixed. A room reached from outside the app (universal link, `-openLink`, push, or an invitation row in Notifications) now opens on the room's card (`RoomsRoute.roomLink`, `RoomLinkScreen`) with an explicit Join button and a Not now button, and nothing but a read reaches the server until Join is tapped. Signed out, the guest shell shows the same card with Listen, and no seat is taken until Listen is tapped (`GuestRoomLinkViewModel` reads only the public lists). Taps inside the app (room cards, Live now, an event's Join, a room just created, the onboarding card, and a guest coming back after signing in from a room they were listening in) still join at once through the new `router.resumeRoomId`. A guest who signs in while a linked room is still on its card is not joined. There is no custom URL scheme: `DeepLink.parse` takes only `https://sila.gmai.sa`. Tests: `Tests/RoomLinkTests.swift` (routing by origin, the card, a guest lookup that never calls `listen`), `Tests/LaunchArgumentGateTests.swift` (the new debug-only `-openLinkAfterSignIn`), UI journeys `UITests/RoomLinkJourneyUITests.swift` (signed in: card, nothing joined, then Join; Not now; Arabic) and `UITests/GuestListeningJourneyUITests.swift` (signed out: card, nothing heard, then Listen; Not now). Before the fix, the old guest journey asserted listening at once with no tap, and the member path pushed `.room`, which joins on appear.
- CA-3 (paths in the app vs the site, iOS half): fixed as a pinned check, with no change to the claimed paths. I fetched https://sila.gmai.sa/.well-known/apple-app-site-association with a passive GET: 200 application/json, app ID 7258Y6294P.com.socialsa.sila, with /posts/*, /u/*, /events/* (excluding /events/new), /rooms/* (excluding /rooms/series/*), /vouch/*, /vouch and /vouching. These match `DeepLink.parse` and `Sila.entitlements` (applinks + webcredentials for sila.gmai.sa) exactly. Test: `Tests/AssociatedDomainsTests.swift` holds a copy of the served components and fails if either side drifts. It covers every path the app reads or shares, every path kept for Safari, the entitlements domains and the app ID. I did not add /c/* or /tags/* on iOS: the app has no deep link for communities or hashtags, so claiming them would open the app on nothing. assetlinks.json and the Android path list belong to the web and Android lanes.
- Also, not a finding: `LocalizationCatalogTests` failed before this change because its key scanner did not know the `settings.` namespace, so the verification-photo keys counted as unused. I added the namespace. The related unit suites and the 13 room-link and guest UI journeys pass (derived data in /private/tmp/claude-501/dd-sec3).
