# v34 review response (iOS lane)

1. [medium] Line 5 named "Settings › Privacy › Verification photos", a screen iOS does not have. **Fixed.** Line 5 is now `…Withdraw any time in %@…`, and the app fills in the route from the labels its own screens show: "Profile › Account › Privacy › Verification photos" / «الملف الشخصي › الحساب › الخصوصية › صور التحقق» (`RetentionConsentCard.withdrawalRoute`). Because the card uses the same strings as the screens, the two cannot drift apart. Tests: `VerificationFilesConsentTests.testLineFiveNamesTheRouteThePersonFollows` (fails on the old wording, which contains "Settings"), and the UI journeys `ConsentCardJourneyUITests.testLineFivesRouteLeadsToTheRowInEnglish/Arabic`, which find each step by the label the card names (tab, entry, sheet title, section, row) and then withdraw. This is an iOS-specific wording of contract §7.2 line 5, so the contract owner should note it. The consent version stays `vf1`.
2. [medium] The card and Send might not fit on the screen. **Fixed.** When the card is shown, the send step drops its "Ready to send" heading and message and uses tighter spacing. Test: `ConsentCardJourneyUITests.expectWholeCardOnScreen`, run in the EN and AR card journeys on an iPhone 15 (iOS 17.2) at the default text size before any swipe. It checks that the title, lines 1–5, the checkbox, the link and Send all sit wholly inside the window and below the navigation bar, and that Send is hittable. The old `if !send.isHittable { swipeUp }` fallback is now an assertion. iPhone SE was not run because the lane asks for an iPhone 15.
3. [low] Try again skipped re-reading the offer. **Fixed.** `retrySend()` now reads `GET /verification/status` first. If the offer changed, it draws the send step again, unticked and with the notice, and sends nothing. If it did not change, it sends with the tick. Tests: `testTryAgainReadsTheOfferAgainAndRedrawsTheCardWhenItChanged` (nil and vf2), `testTryAgainWithTheSameOfferSendsTheTick`.
4. [low] `retention_consent_required` was not in the contract and could block Send. **Fixed.** Removed from `VerificationStatusReport`, the mock and the `-mockConsentRequired` flag. `canSend` is now just `!isSubmitting`. Test: `testNoStatusKeyCanBlockSendWithoutTheTick` (status carries the key set to true; Send stays enabled and the submission goes without consent).

   - (1) Rejected-screen wording: **fixed.** The choice moved into `RejectedScreen.explanationKey` / `photosKept(in:)`. Test: `testTheRejectedScreenSaysKeptOnlyForAKeptCase` covers with_account/true, with_account/false, until_decision, a pre-v34 case and no case.

   - (3) UI journey for the photos row: **fixed** by the route journeys in item 1.
